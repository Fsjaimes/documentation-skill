Preparación del entorno

Dos terminales en paralelo

Se necesitan dos consolas abiertas simultáneamente: una mantiene el worker de colas activo, y la otra ejecuta los comandos de importación. La Terminal 1 debe estar corriendo antes de lanzar cualquier comando en la Terminal 2.

Terminal 1 — Worker
# 1. Entrar al contenedor
$ docker exec -it laravel_app_suite bash

# 2. Levantar el worker de colas
$ php artisan queue:work

→ Dejar corriendo durante toda la importación
●

¿Qué hace queue:work?

Mantiene un proceso escuchando la cola de Laravel y ejecuta los jobs de importación a medida que el comando import los encola. Sin este proceso activo, los registros no se insertan en la base de datos.

Terminal 2 — Importación
# 1. Entrar al contenedor
$ docker exec -it laravel_app_suite bash

# 2. Ejecutar comandos de importación
$ php artisan import …

→ Ver siguiente sección para el orden exacto
●

Consejo

Abre ambas terminales antes de empezar. Una vez que la Terminal 1 muestra el worker activo, ya puedes proceder con los comandos en la Terminal 2.

Orden de ejecución

Comandos de importación

Respetar el orden es obligatorio: los productos referencian a terceros, por lo tanto los terceros deben importarse primero.

▲

Empezar siempre por terceros

Si se importan productos antes que terceros, los registros quedarán con referencias rotas y deberás reimportar.

1 Importar terceros
php artisan import third_parties
Lee por defecto: public/imports/third_parties.json
2 Importar productos · equipos
php artisan import products develop
Lee por defecto: public/imports/develop/products.json — registros tipo EQUIPO
3 Importar productos · artículos
php artisan import products develop --file=public/imports/develop/products_articles.json
Se indica el archivo explícitamente con --file — registros tipo ARTICULO
Verificación

Auditar la importación

Una vez finalizada la importación, consultar la tabla import_row_logs en la BD del tenant para identificar registros que no se procesaron correctamente.

SQL · tenant DB
SELECT * FROM public.import_row_logs WHERE status != 'ok' ORDER BY id ASC;
●

Cómo interpretar el resultado

Cada fila con status distinto de ok indica un registro que falló y debe revisarse manualmente. La causa más común: falta alguno de los registros maestros listados en Prerrequisitos, o el JSON contiene un código que no existe en los catálogos de la base de datos.

Referencia rápida

Todos los comandos en un solo lugar

Para quien ya conoce el proceso y solo necesita copiar y pegar.

Todos los comandos
# Terminal 1
$ docker exec -it laravel_app_suite bash
$ php artisan queue:work

# Terminal 2
$ docker exec -it laravel_app_suite bash
$ php artisan import third_parties
$ php artisan import products develop
$ php artisan import products develop --file=public/imports/develop/products_articles.json
Verificación post-importación
-- Registros con error SELECT * FROM public.import_row_logs WHERE status != 'ok' ORDER BY id ASC; -- Conteo total de errores SELECT COUNT(*) FROM public.import_row_logs WHERE status != 'ok';
